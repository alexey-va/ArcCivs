# Fence neighbour-state recovery — 0.1.73

At 2026-10-24 14:16:30 UTC, Spawn/Auto's paid QUARRY upgrade `1c6bc9ac-907f-4fc0-b23a-924c9ecd99fa` stopped at batch 141/274, with 211/366 blocks placed. The existing spruce fence at (-409,71,-572) retained its material and waterlogging, but its north/west neighbour connections changed before replacement by the planned spruce trapdoor. The native construction guard treated that derived state change as `autonomy-terrain` and persisted PAUSED. The verified 14:29:51 UTC layout export still contains that same paused order, target building `051c8ecb-8fbb-45e2-8fb8-fc7e66be96f0`, cost 80 abstract wood/80 stone, and workCredit 51.

The shared state comparator already tolerates the neighbour-derived corner shape of stairs. It now also tolerates the four horizontal connections of Bukkit `Fence`, only when materials match. It copies those four booleans from expected data into a clone of actual data and then compares the complete state. Material, waterlogging and other properties remain exact. This is not a general `MultipleFacing` exception: vines, gates, trapdoors, containers, protection and foreign block states keep their existing checks. Neither input BlockData is mutated.

Pinned Purpur 1.21.11 `FenceBlock.updateShape` recomputes the horizontal connection through `connectsTo` for a neighbour update. Its waterlogging branch only schedules a fluid tick. The same helper is already used by both construction preflight and the final native write gate, so neither caller needs a bypass.

The pause is durable and is intentionally not retried automatically: `autonomy-terrain` can also mean a real protected obstruction. After the corrected runtime is verified, the existing admin console command `civs retry-construction <city UUID>` retries the original saved order through ordinary validation. It preserves order ID, captured plan, batch progress, materials and cost; it does not create or reprice an order. Recovery requires subsequent native batch commits and observed progress, not a command acknowledgement or teleport alone.

The 80 wood/80 stone payment is not repeated. No limit, unit price, output amount, native item issuance or currency rule changes. Direct deltas remain separately zero Vault, zero premium tokens and zero player XP; existing SELL and the planned SELL-to-contract transition are unchanged. Any restored production is reported as observed work rather than a new nominal earning rate.

The release also contains the 0.1.72 infrastructure demand correction. It does not resolve the separate full-cap/terrain/crossing limitations of Auto's walls or activate the offline V2 layout. Validation, exact CI artifact, delivery, activation and same-order recovery are recorded separately in the operations report.
